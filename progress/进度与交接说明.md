## 三、关键结论与证据等级

1. **召回（诉求③）——`[实测]`，但「强于关键字」仍未获证明**
   - BM25-only 基线（Logseq-only 428 md / 26 query / 文件级主口径）：**recall@1 0.6154 / @3 0.7692 / @5 0.8462 / @10 0.8462、MRR 0.7003**。
   - M2 向量 hybrid：线上 3072 维、本地 bge-base-zh / jina（768 维）**三版全部未强于 BM25-only**。
   - 改进对照（T33/T34，预注册、先定后跑、无择优）：**加权 RRF（3:1/2:1/1:1）与召回并集均未取胜**（稀释中文首位命中）；**表面路由仅 jina 非劣**（bge 打平）→ 不构成「强于」；**标题 token ×4 提升的是 BM25 本身**（@1 0.6154→0.6923、MRR→0.7474）；**D1×B 叠加对公平基准 D1-BM25×4 仍未强于**。
   - **总账**：稳定且**模型无关**的净增益只有一个——**标题×4（词法侧）**。所有 hybrid 增益**只来自跨语言 query 的选路**（Q13/Q15），中文 22→24 条首位命中**一分未涨**。→ **全文严禁写成「已强于关键字」**。
2. **导入（诉求②）——`[实测]`**：为知**跳过**（导出物仅目录骨架）；改走**通用「带附件 Markdown 目录」**通路，真实 Logseq graph **428 md / 204 附件 / 相对引用可解析率 100% / 丢失清单空**；**解析器自检 16/16 为强制前置**（朴素正则曾伪报 44.7%）。
3. **写入（诉求⑥）——`[实测]`（最小实现）**：两阶段写（`propose_write` → 受信签发一次性 token → `commit_write`）、单例 daemon 解决多宿主并发丢写（直写 8×50 期望 400 实得 37 → 单例 daemon 丢 0）。
4. **密钥/反填（诉求④）——设计成立、端到端未实测**：知识库零明文、只存指针，凭据由 **Bitwarden** 持有；主用途 = **供 AI agents 运行时取用**（人手工反填暂不做）。
5. **宿主支持面（R11/Q16）**：`[实测]` harness 连接器由宿主 SQLite 管理、支持 stdio、存在审批记录子系统；**渲染/审批行为仍 `[Q]`**（目标客户端 Cursor / deepseek harness）；**Cursor progress 由用户人工判定「通过」**（UI 不稳，依据是人工观察、非日志实证）。
6. **UI 呈现验证（诉求①/⑥）**：原型已用 headless Chrome 实测（见下文 2026-10-29 第二项，0 问题）；真实宿主内渲染 / 屏幕阅读器**仍空缺**，不得视为整体已验证；200% 缩放与纯键盘全流程已由 `ui-check` 覆盖（2026-10-29）。
