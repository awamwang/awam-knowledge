## 1. 产品定位与价值主张

### 1.1 一句话价值主张

> **用一个本地可控、可自接 MCP 的"对话式知识层"，替代需要人工维护界面的 Notion / Logseq / 为知笔记——知识以本地文件为唯一真相源，召回用语义混合检索（强于关键字），密钥与知识物理隔离（只存指针、运行时取用），任何写入都要你点头。**
> `[E]` 依据：源文档"需求"段 + "用户选择（本地可控、自己接 MCP）"；`[选型依据]` 召回/密钥/起步最小集来自源文档"回答 2 本地栈建议"。

### 1.2 定位三支柱

| 支柱 | 含义 | 依据 |
|------|------|------|
| **对话优先、弱化界面** | 检索与录入主入口是 AI 会话，不做 Notion 式管理界面；界面只保留"确认/查看/撤销"等写入门与状态可见性 | `[E]` 诉求①⑤；T1 §7.2 `[A]` 最小 UI 判断 |
| **本地可控、自接 MCP** | 数据落本地文件/本地库；MCP 是访问层而非唯一存储；同一套栈可挂 Cursor/Claude 等多个助手 | `[E]` 源文档"用户选择"；T1 JTBD-6 |
| **知识与密钥物理隔离** | 知识库只存"哪有账号、怎么用"的**指针/引用**，绝不存明文秘密；密钥本体由 1Password/Bitwarden 类工具持有，运行时取用 | `[E]` 源文档"安全/密钥"；T1 §7.3 |

### 1.3 我们是什么 / 不是什么

| 我们是 | 我们不是 |
|--------|----------|
| 本地优先的**个人**知识层（P0：技术型、单人自用） `[A]`(T1 A1) | 面向大众的 SaaS / 云同步为中心的托管产品 `[Q]`(T1) |
| 对话式召回 + 会话式录入的**访问层** | Notion 式的目录/排版/看板**管理界面** |
| MCP 生态里的**一组 skill/连接器**（知识 MCP + 密码管理器 MCP/CLI） | 单一万能 Agent / 自研密码管理器 |
| 以 Markdown 文件为唯一真相源的**可迁移**方案 | 封闭第二大脑、数据锁定的黑盒 |

`[选型依据]` "本质是 记忆/RAG MCP + 密码管理器连接器 两个 skill 拼起来，而不是单一万能 Agent" —— 源文档"技能形态"。

## 2. 能力域分解（五层 + 一个横切层）

总览：**本地文件（真相源）→ 知识 MCP（读/写接口）→ AI 助手（会话）**；密钥侧独立为**密码管理器 → 密钥连接器**，与知识层零明文耦合。

```
        ┌────────────────── AI 会话与写入边界层（L5） ──────────────────┐
        │  对话召回（读，放开）        会话录入（写，需确认闸门）        │
        └───────────▲───────────────────────────────────▲────────────┘
                    │ MCP: search                          │ MCP: add/update（确认后）
        ┌───────────┴───────────────────────────────────┴────────────┐
        │           存储与召回层（L2）：Markdown 真相源 + 向量/BM25 索引 │
        └───────────▲─────────────────────────────────────────────────┘
                    │ 切块/嵌入/写入
        ┌───────────┴───────────┐        ┌───────────────────────────┐
        │      导入层（L1）      │        │   安全与密钥层（L3）       │
        │ Notion / Logseq / 为知 │        │ 1Password / Bitwarden      │
        └───────────────────────┘        └───────────▲───────────────┘
                                                     │ 指针/引用 + 运行时取用
                                         ┌───────────┴───────────────┐
                                         │        反填层（L4）         │
                                         │ 指针化 · 运行时取用 · 脱敏  │
                                         └───────────────────────────┘
        ┌──────────────── 横切：配置与适配层（L6）· MCP 接线 ─────────────┐
        └──────────────────────────────────────────────────────────────┘
```

### L1 导入层

| 项 | 内容 |
|----|------|
| **职责** | 把 Notion / Logseq / 为知笔记的历史知识一次性搬入本地真相源，尽量保留结构与元数据 |
| **关键约束** | 本地执行、不依赖原工具在线；导入产物是可读的本地文件；导入过程不改动原工具数据（只读原库）；**三来源差异大，须按来源分通路，不强求统一管道** |
| **可选实现方向** | ① Logseq：优先试 `[Q]` mcp-logseq 只读接入（能直连则"引用/同步"优于"复制"），退路是解析其 Markdown 库；② Notion：用其导出（Markdown & CSV）后做本地归一化；③ **为知笔记：成本/风险最高的来源**——导出格式未确认（`[Q]` T1 Q2），须单列**独立适配层**（格式解析 + 附件处理 + 归一化），不与 Markdown 系通路混用 |
| **优先级** | **P0**（诉求②，用户核心诉求之一），但**分来源分批交付**：先打通 Markdown 系（Logseq/Notion 导出），为知格式确认后再补 |
| **依据** | `[E]` 诉求②；T1 JTBD-2、§7.4"导入是关键风险点"；`[选型依据]` 源文档"起步最小集"未含导入 → 说明导入可后置于最小闭环；为知列最高成本/风险与独立适配层 —— 依据设计负责人转述的 `00-precheck-notes.md` 预研口径（该文件待回灌核对） |

**导入保真度目标（需在实现前定义并实测）**：条目数一致率、标签/双链保留率、附件可用率三项量化；无法保留的项必须记录为"丢失清单"，不得静默丢弃。`[A]`

### L2 存储与召回层

| 项 | 内容 |
|----|------|
| **职责** | 持有知识真相源；提供切块+嵌入索引与混合（BM25+向量）召回接口 |
| **关键约束** | 真相源必须是本地文件/本地库（可迁移、可被外部编辑）；MCP 仅是访问层；索引可由真相源重建（索引不是唯一存储） |
| **可选实现方向** | 真相源：Markdown/纯文件夹（首选，可迁移）`[Q]`(T1 Q10 待定)；索引：自建 SQLite/LanceDB + hybrid（BM25+向量），或复用现有本地知识 MCP（如 Knowz/Cerefox）`[选型依据]` 源文档"回答 2 · 知识层/召回"；图谱：**可选、延后**（源文档称"重要实体可再加简单图谱"）`[Q]`(T1 Q13) |
| **优先级** | **P0** —— 这是系统的心脏，也是"召回强于关键字"的落点 |
| **依据** | `[E]` 诉求①③；T1 JTBD-1、§7.5"真相源本地化" |

**召回策略**：入库时切块 + 嵌入；查询走 hybrid（BM25 精确词 + 向量语义），支持换述/同义/模糊记忆召回。`[选型依据]` 源文档"召回"段明确 hybrid；T1 §7.7 要求把"更强"落成可测标准。

### L3 安全与密钥层

| 项 | 内容 |
|----|------|
| **职责** | 管理账号/密钥，提供"指针注册 + 运行时取用"接口；保证知识库零明文 |
| **关键约束** | 知识库、向量库、日志、导出物中**零明文 secret**；知识库只存**指向密钥的指针/引用**（账号名、用途、定位符）；secret 不进 AI 上下文（或仅以引用占位符出现）；不自研密钥库，复用成熟密码管理器 |
| **可选实现方向** | 本机 1Password / Bitwarden + 其 MCP 或 CLI；知识库存"账号名、用在哪、怎么用"的引用条目，运行时按引用取用 | `[选型依据]` 源文档"密钥层"与"回答 1 · 安全"明确"Agent 只调填充/取用接口，正文不存明文" |
| **优先级** | **P0**（诉求④安全半边） |
| **依据** | `[E]` 诉求④、S4/S9；T1 JTBD-3、§7.3 |

**隔离级别待定**：取用时 Agent 是"直接读到 secret"还是"仅触发取用动作"（不经 Agent 上下文）——后者更安全，`[Q]` 见 T1 Q11，建议按"Agent 不接触明文、只传指针"设计。

### L4 反填层

| 项 | 内容 |
|----|------|
| **职责** | 在用户需要登录/用到密钥时，按**指针**在**运行时**取用凭据并填充到目标位置；全程**脱敏** |
| **关键约束** | 反填由用户主动触发；**指针化**（知识库只存引用，不存值）+ **运行时取用**（需要时才由密码管理器取出）+ **脱敏**（明文不落知识库/日志/AI 上下文）；先小范围（单场景）验证再扩 |
| **可选实现方向** | 复用密码管理器自带的浏览器扩展 / CLI 填充能力，系统只负责按指针定位并触发取用 |
| **优先级** | **P1**（诉求④可用半边）——触发场景 `[Q]` 未确认（T1 Q4：浏览器/终端/App？），先做最可能的一种，避免过度设计 |
| **依据** | `[E]` 诉求④(S5)；T1 JTBD-3、Q4 |

**表述纪律**：本方案只承诺"**指针化 + 运行时取用 + 脱敏**"的机制方向；**禁止表述为"一键反填到任意表单已实现"**——跨表单/跨应用的通用自动填充属未验证能力，`[Q]` 待原型验证（依据设计负责人要求）。

### L5 AI 会话与写入边界层

| 项 | 内容 |
|----|------|
| **职责** | 提供对话式召回（读）与会话式录入（写）；实现"写入需用户确认"的闸门 |
| **关键约束** | **读放开、写收紧**：召回无需确认；任何写入（新增/修改/删除）必须经用户显式确认；写入应可撤销、可审计；召回"未找到"时须如实说"没找到"，不得编造 |
| **可选实现方向** | 由 AI 助手（Cursor/Claude 等）+ 知识 MCP 的 `search`/`add`/`update` 完成；写入前弹出确认（逐条/批量待定 `[Q]` T1 Q5）；会话中自动"建议落库"也必须走确认 `[Q]`(T1 Q14) | `[选型依据]` 源文档"Agent 只通过 MCP 的 search/add/update 读写" + 任务约束"收入知识管理需用户确认" |
| **优先级** | **P0**（诉求⑤⑥，且"写确认"是不可妥协的安全阀） |
| **依据** | `[E]` 诉求⑤⑥(S6/S7)；T1 JTBD-4/5、§7.1"读放开写收紧" |

### L6 横切 · 配置与适配层（MCP 接线）

| 项 | 内容 |
|----|------|
| **职责** | 让知识 MCP 与密钥连接器可被多个 AI 助手复用；管理本地配置 |
| **关键约束** | 配置本地化、可迁移；一套栈挂多端，不绑定单一助手；配置中不落 secret 明文 |
| **可选实现方向** | 标准 MCP 配置 + 环境变量/密钥管理器引用（secret 不落配置文件明文 `[Q]` 待确认） | `[选型依据]` 源文档"Cursor/Claude/助手侧都能挂同一套" |
| **优先级** | **P1** |
| **依据** | `[E]` 前提 S8；T1 A2、JTBD-6 |

**能力域优先级汇总**：L2、L5 = P0 核心；L3 = P0 安全基石；L1 = P0 但分批；L4、L6 = P1。

## 4. MVP 最小起步集

**目标**：先跑通"**本地库 → 知识 MCP → 会话召回 → 会话录入（确认后落库）**"的可用闭环，并把密钥**隔离**到位。

`[选型依据]` 源文档"起步最小集"仅含三项：① 一个笔记目录 ② 一个知识 MCP ③ Bitwarden / 1Password。T2 在此基础上补齐**写入确认闸门**（用户明确的硬约束）与**最小导入通路**。

| # | MVP 组件 | 说明 | 优先级 |
|---|----------|------|--------|
| M1 | 一个本地笔记目录（Markdown 为真相源） | 唯一真相源，可迁移、可外部编辑 | P0 |
| M2 | 一个知识 MCP（hybrid 召回 + add/update 接口） | 切块+嵌入、BM25+向量混合检索 | P0 |
| M3 | 密码管理器（Bitwarden / 1Password）+ 指针化取用接口 | 密钥隔离，知识库零明文、只存指针 | P0 |
| M4 | 读写通道：`search`（读，放开）/ `add`·`update`（写，需确认） | 落实"读放开、写收紧" | P0 |
| M5 | 写入确认闸门（含撤销） | 诉求⑥落地 | P0 |
| M6 | 最小导入通路（≥1 条：Logseq Markdown 或 Notion 导出） | 证明导入可行；为知经独立适配层后置 | P0(首批) |
| M7 | 反填基础能力（**指针化 + 运行时取用 + 脱敏**，单场景验证） | 需求④可用半边；**不承诺"一键反填到任意表单"**，先做可行性验证 | P1 |

**MVP 完成定义（DoD）**：用户能在一个 AI 助手里，用自然语言问出以前记过的知识（语义、非关键字），能把一段对话内容经确认后写入本地库，且知识库与导出物中扫描不到任何明文密钥、仅存指向密钥的指针。

## 5. 首版不做（非目标）

| # | 首版不做 | 理由 |
|---|----------|------|
| N1 | **Notion 式管理界面**（目录树/拖拽排版/看板/多维表） | 与"弱化界面、对话优先"定位冲突 `[E]`诉求① |
| N2 | **多人协作 / 共享 / 权限体系** | 源文档只谈个人知识管理，无协作诉求 `[Q]`(T1 §2.3) |
| N3 | **非技术用户免配置 / 托管 SaaS / 以云同步为卖点** | 与"本地可控、自己接 MCP"前提冲突 `[E]`S8 |
| N4 | **自研密码管理器** | 复用成熟工具更安全，源文档明确"密钥放 1Password/Bitwarden" `[E]`S9 |
| N5 | **三种来源的"完美保真导入"** | 源文档无一手续费信息，为知格式未确认 `[Q]`(T1 Q2/Q3)；为知须独立适配层，保真度分级并记录丢失项 |
| N6 | **知识图谱 / 实体关系**（首版） | 源文档称"可选、重要实体可再加"；先验证混合检索是否已够 `[Q]`(T1 Q13) |
| N7 | **原工具的持续双向同步**（首版） | 导入定位为"一次性迁移"优先；是否需持续同步待确认 `[Q]`(T1 Q12) |
| N8 | **移动端原生 App**（首版） | 无相关诉求证据 `[A]`，避免复杂度反噬 |

## 6. 成功指标与验收标准

### 6.1 召回质量（诉求①③）
- **指标体系**：建立 20–30 条真实查询评测集（含"记得意思、想不起词"的换述查询），对照基线 = 现有 Logseq/为知的关键字搜索。
- **验收标准**：
  - `[A]` Top-1 首选命中率 ≥ 70%，Top-5 召回率 ≥ 90%（阈值需 T5/访谈校准，`[Q]` T1 Q9）；
  - 换述/同义查询命中率**显著高于**关键字基线；
  - **无结果时如实返回"未找到"**，不得由 AI 编造答案。
- **依据**：`[E]`诉求③；T1 §7.7 要求把"更强"转为可测指标。

### 6.2 密钥不外泄（诉求④安全）
- **验收标准**：
  - 知识库正文、向量索引、运行日志、导出物中 **明文 secret 命中数 = 0**（自动化扫描）；
  - 知识库只含**指针/引用**，值与 secret 分离；
  - secret 不进入 LLM 上下文（或仅以占位符/引用出现）；
  - 迁移/导出知识库时，带走的只是"引用关系"，不带任何凭据。
- **依据**：`[E]`S4/S9；T1 §7.3。

### 6.3 写入可确认（诉求⑥）
- **验收标准**：
  - **100% 写入（add/update/delete）经用户显式确认**，无静默写入路径；
  - 写入可撤销，并保留审计信息（来源=哪次会话、时间）；
  - AI 的"建议落库"同样走确认流程。
- **依据**：`[E]`S7；T1 JTBD-5、§7.1。

### 6.4 本地可控与可迁移（既定前提）
- **验收标准**：
  - 全部知识数据落在本地文件/本地库；**断网时核心召回仍可用**；
  - 更换 AI 助手（Cursor↔Claude 等）无需迁移数据；
  - 索引可由真相源重建，删除索引不丢知识。

### 6.5 导入保真（诉求②）
- **验收标准**：对每条已实现通路，给出并实测**条目数一致率 / 标签·双链保留率 / 附件可用率**；无法保留项进入"丢失清单"并可见；为知通路单独出具适配层评估。
