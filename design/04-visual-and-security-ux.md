## 0. 本文边界与设计立场

### 0.1 视觉要服务的唯一核心

主入口是 **AI 会话**，不是页面导航。因此本方案的视觉工作**不是设计一个 App**，而是设计：

1. **会话流里的三类"系统卡"**（结果卡 / 确认卡 / 导入卡）如何被看懂；
2. **一个安全层**（密钥）如何被"看见存在、看不见内容"；
3. **一套够用的组件与 token**，让 T5 原型可以直接落地。

### 0.2 最小 UI 的界定（什么画、什么不画）

| 要设计（在范围内） | 不设计（明确排除，依据 T2 §1.3 / §5） |
|--------------------|----------------------------------------|
| 对话流与内嵌卡片 | Notion 式目录树 / 拖拽排版 / 看板 / 多维表（N1） |
| 写入确认卡（含差异与撤销） | 富文本编辑器 / 排版工具栏（与"写收紧"冲突） |
| 召回结果卡（来源、片段、展开） | 知识库全量浏览页（可留只读"来源查看"，非管理） |
| 导入向导（进度、保真度、丢失清单） | 导入后的持续双向同步界面（N7） |
| 账号引用条目 + 反填触发 + 脱敏态 | 自研密码管理器界面（N4：复用成熟工具） |
| 状态与审计的可见性（轻量徽标/状态条） | 多人协作 / 权限 / 分享界面（N2） |

> `[A]` 结论：视觉复杂度预算应压在**卡片状态机**与**脱敏表达**上，而非页面数量。页面数越少越好。

### 0.3 一条贯穿原则：克制的状态可见性

T2 §2.5 要求"读放开、写收紧"。视觉上必须让用户**随时能感知三件事**而无需开管理页：
1. 我现在的写入是否待确认 / 已确认 / 已撤销；
2. 一个账号引用是"存在但不可见"还是"不存在"；
3. 召回是"命中真实来源"还是"未找到"（不得编造，T2 §6.1）。

这三件事用**同一套状态视觉语言**（见 §1.5），不各造一套。

## 1. 视觉基调与信息层级

### 1.1 基调关键词

**本地工具感 / 内容本位 / 低装饰 / 长时可读 / 安全感可被"看见"。**

- 不做营销式大色块、圆润插画、渐变——它们与"私人本地工具"心智不符 `[A]`。
- 不用饱和色堆叠来制造层级；层级靠**间距、字重、边框、留白**建立。
- 默认**暗色**为第一主题（本地工具、长时间阅读、开发者向 `[A]`，依据 T1 用户为技术型个人），同时提供等价的浅色主题；两套主题共享同一 token 语义。

### 1.2 色彩系统

设计立场：**中性灰阶打底 + 单一品牌强调色 + 三组语义色 + 一组"保险库色"**。颜色只承载语义，不承载装饰。

| Token（语义） | 暗色 | 浅色 | 用途 | 对比要求 |
|---------------|------|------|------|----------|
| `bg/base` | `#0E1116` | `#FAFAF9` | 页面底 | — |
| `bg/surface` | `#161B22` | `#FFFFFF` | 卡片、结果卡 | — |
| `bg/subtle` | `#1F242C` | `#F2F2F0` | 引用块、代码、导入预览 | — |
| `border/line` | `#2A313B` | `#E4E4E1` | 分隔、卡边 | ≥3:1 对相邻底色 |
| `text/primary` | `#E6E9EE` | `#1A1D21` | 正文、标题 | ≥ 4.5:1 对 `bg`/`surface` |
| `text/secondary` | `#9BA3AF` | `#5B6470` | 元信息、来源、时间 | ≥ 4.5:1；低至 4.5 底线 |
| `text/disabled` | `#5C6672` | `#A3A8AE` | 禁用 | 不用于关键信息 |
| `accent/primary` | `#5B8CFF` | `#2F6BFF` | **唯一**主操作色（确认、主按钮、焦点环） | 按钮文字 ≥ 4.5:1 |
| `semantic/success` | `#3FB950` | `#1F883D` | 已确认、导入成功 | 配图标，不单靠色 |
| `semantic/warning` | `#D29922` | `#9A6700` | 待确认、保真度警告、丢失项 | 配图标 |
| `semantic/danger` | `#F85149` | `#CF222E` | 删除、撤销、风险 | 配图标 |
| `vault/secret` | `#A371F7` | `#7C3AED` | **密钥/保险库专属**（引用条目、脱敏态、反填） | 配锁图标 |

**规则：**
- **`vault/secret` 色只用于账号引用与密钥相关**，形成"紫色=保险库"的稳定心智，让用户一眼区分"普通知识"与"账号引用"。
- 语义色**永不单独承载信息**：一律"颜色 + 图标 + 文字标签"三件套（色盲安全，见 §4.3）。
- 强调色（`accent/primary`）全站**只有一种**，避免多处争抢注意力。
- 反差：正文/按钮文字对底 `≥ 4.5:1`；大字号（≥18.66px 或 14px 粗体）与 UI 图形边界 `≥ 3:1`（WCAG 2.1 AA）。

### 1.3 字体与排版

| 用途 | 字体族 | 说明 |
|------|--------|------|
| 正文 / UI | System UI 栈：`Inter, -apple-system, Segoe UI, PingFang SC, Microsoft YaHei, sans-serif` | 中英混排稳定，零网络依赖（本地优先）`[A]` |
| 等宽 / 标识符 | `JetBrains Mono, SF Mono, Cascadia Code, Consolas, monospace` | **路径、条目 id、账号引用 token、代码块、哈希**一律等宽 |
| 标题 | 同正文族，靠字重/字号区分 | 不引入展示型字体 |

**字号阶梯（1.25 比率，base 16px）：**

| 名称 | 字号 / 行高 | 用途 |
|------|-------------|------|
| `text/caption` | 12 / 16 | 时间戳、来源徽标、审计附注 |
| `text/small` | 13 / 20 | 元信息、卡片副标题、按钮小号 |
| `text/body` | 14–16 / 22–24 | 对话正文、卡片正文（默认 16，密度高时 14） |
| `text/lead` | 20 / 28 | 结果卡标题、确认卡主标题 |
| `text/title` | 24–32 / 32–40 | 仅导入向导等全屏步骤页 |

**排版规则：**
- 正文行宽上限约 **72–84 字符**（`~720–840px`），保证长文可读。
- 段落间距 > 行距，用留白而非缩进分层。
- **账号引用 token、文件路径、账号名必须等宽**，且用户可一键复制（复制的是**引用/占位符**，不是明文，见 §3）。

### 1.4 间距、圆角、栅格

- **间距基数 4px**，步进档：`4 / 8 / 12 / 16 / 24 / 32 / 48`。层级靠间距差建立，不靠色差。
- **圆角**：卡片/输入 `10px`，小徽标/按钮 `6px`，大容器 `14px`。统一，不作装饰性变化。
- **栅格**：会话优先的**单列**布局，内容列居中，最大宽 `840px`。
  - 侧栏**不是目录树**，仅承载"待确认队列 / 审计与撤销入口 / 连接器状态"这类**状态可见性**短区（依据 T2 §0.2 最小 UI 边界）。侧栏可折叠，默认在宽屏展开、窄屏收起为顶栏徽标。
- 触控/点击目标最小 `44×44px`（含内边距）`[A]`（对齐 WCAG 2.5.5 建议）。

### 1.5 信息层级：三层视觉语言（贯穿全站）

| 层级 | 名称 | 视觉表达 | 例子 |
|------|------|----------|------|
| L0 | **对话基底** | 无容器，纯文本；用户/AI 靠对齐与头像区分，不靠气泡色块堆叠 | 提问、回答正文 |
| L1 | **系统卡** | `bg/surface` + 1px `border/line` + 左侧 `3px` 语义色竖条 | 结果卡、确认卡、导入卡 |
| L2 | **状态徽标 / 状态条** | 小圆角胶囊（图标+文字，等宽或 small 字号） | `待确认`、`已确认·可撤销`、`未找到`、`🔒 Bitwarden 引用`、`保真度 92%` |

**L1 卡片状态机（三类卡片共用一套"边色 + 徽标"语言）：**

| 状态 | 左边条色 | 徽标 | 关联界面 |
|------|----------|------|----------|
| 待确认（写入） | `semantic/warning` | `待确认` | 写入确认卡 |
| 已确认 | `semantic/success` | `已确认 · 可撤销` | 写入确认卡（完成态）/ 状态条 |
| 已撤销 | `text/secondary` | `已撤销` | 审计条目 |
| 命中（召回） | `accent/primary` | `命中 N 条` | 召回结果卡 |
| 未找到 | `text/secondary` | `未找到`（**无伪造内容**） | 召回结果卡（空态） |
| 账号引用 | `vault/secret` | `🔒 账号引用` | 反填浮层 |
| 低置信候选 | `semantic/warning` | `低置信 · 候选` | 召回结果卡（E-02） |
| 撤销已过期 | `text/secondary` | `已确认 · 撤销已过期` | 审计条目（E-14） |
| 保真度告警 | `semantic/warning` | `丢失 N 项` | 导入向导结果步 |

> `[A]` 这套状态语言是本方案最该被 T5 原型优先验证的部分——用户能否只凭边色+徽标判断"这条到底写进去了没有"。
> 修订说明（依 T5 §6 裁决）：本表在"命中 / 未找到"两档之外，新增「低置信候选」（E-02）与「撤销已过期」（E-14）两态，此前缺失，现补齐。

### 1.5.1 状态可见性三项（V0 顶部常显）规格

对应 T3 §6「状态可见性总则」：会话顶部常显三个状态点，用户任何时刻都能回答"我在哪、能不能用、下一步去哪"。

| 状态点 | 🟢 | 🟡 | 🔴 | 色值（复用语义色） | 文字标签（必须显示） |
|--------|----|----|----|--------------------|----------------------|
| **召回可用性** | 召回可用 | 降级（仅关键字兜底） | 离线 / 断连（MCP 不可用） | `semantic/success` / `warning` / `danger` | 召回可用 / 降级 / 离线 |
| **密钥工具连接** | 已连接 | 未连接 | 连接异常 | 同上 | 密钥工具已连接 / 未连接 / 异常 |
| **索引状态** | 就绪 | 构建中 | 未就绪 | 同上 | 索引就绪 / 构建中 / 未就绪 |

- **不新增色值**：三点直接复用 `semantic/success|warning|danger`（暗/浅两主题各取对应值）。
- 每点**必须带文字标签**（色盲安全，见 §4.3），不靠颜色单独传意；🔴 断连态对应 T3 E-13，文案附"恢复后自动重连"。
- 规格：圆点直径 `8px`，对底色对比 ≥ 3:1（不足时加 `1px` 描边），旁附标签用 `text/small`；`🟡` 对应 T3 E-03 / E-06 的降级态。

```
      ├───────────────────────────────────────────────────┤
      │ ● 来源：notes/logseq-issues.md#L7                 │
      │   [展开全文] [复制引用]              ↩ 相关度 0.66 │

      │ 在本地知识库中没有匹配到相关记录。                │
```

**设计要点：** 每条结果**必须带来源路径 + 行号**（可核查、建立信任）；相关度用弱化数字而非进度条（避免过度暗示确定性）；"未找到"是**一等状态**，视觉上明确、不可被 AI 文字糊弄过去。
- **低置信候选（E-02）**：命中弱 / 语义模糊时降级为**候选列表**——卡边色 `semantic/warning`、徽标「低置信 · 候选」，并显式文案"以下可能相关，请确认"（对齐 T3 E-02）。

```
      │  + stdio → sse，timeout 60s                       │
      │ ── 来源 ────────────────────────────────────────── │
      │  来自本次会话 · 2026-10-17 19:52 · 会话 #a13f     │
      │ ── 安全 ────────────────────────────────────────── │
      │  ✔ 未检出密钥明文（脱敏扫描通过）                 │
      │                                                   │
      │      [ 放弃 ]   [ 编辑后存 ]   [ 确认写入 ]       │
      └───────────────────────────────────────────────────┘
AI：  ┌─ 已确认 · 可撤销 ────────────────────────────● ✔ ┐   ← 左边条=success
      │ 已写入 notes/ai/mcp-notes.md（+4 行）             │
      │                     [ 撤销本次写入 ]              │
      └───────────────────────────────────────────────────┘
```

**设计要点：**
- **100% 写入经确认**（T2 §6.3）：卡上永远有明确的"确认/编辑/放弃"三选，无静默路径。
- **差异预览**（`+ / -` 行）让用户知道"到底改了什么"，符合"写收紧"。
- 写入后转为**可撤销**状态并显示来源会话与时间（审计可见性）。
- 确认前做**密钥明文扫描提示**（联动 §3）：若检出疑似 secret，卡片升级为 `semantic/danger` 并阻止直接写入。
- **撤销窗口过期（E-14）**：超过撤销时限后，卡片由「已确认 · 可撤销」转为「已确认 · 撤销已过期」（`text/secondary` 边色），仅提示"该写入已超出撤销窗口"，不再提供一键撤销（对齐 T3 E-14）。
- `[Q]` 确认粒度（逐条/批量）待 T3/T1 Q5 定；本卡布局对两者都兼容（批量时差异区折叠为 N 条 + 汇总，底部按钮不变）。

### 2.4 界面 D · 账号引用 / 反填浮层（脱敏 + 主动触发）

```
── 知识库中的账号引用条目（紫色=vault）──────────────────
   ● 🔒 账号引用 · vault:github/pat#1                 ← 左边条=vault/secret
     账号：github-work            （知识库只存"哪里有账号"）
     用途：CI token，用于 repo X
     存放：Bitwarden  ▸ 保险库默认  （不显示任何 secret 字符）
     可用操作：[ 复制引用 ]  [ 反填到剪贴板 ]  [ 反填到当前窗口 ]
     审计：最近使用 2026-10-16 09:12 · 会话 #b204

── 用户点击"反填到当前窗口"后（由密码管理器执行，不经知识系统）──
   ● 🔒 正在填充…  目标：VS Code 集成终端
     ┌────────────────────────────────────────────┐
     │ ✔ 已通过 Bitwarden 填充，系统未接触明文。   │
     │   本页不显示、不缓存、不记录 secret。       │
     └────────────────────────────────────────────┘

── 若用户坚持要求"显示"（受限态，且默认仍掩码）──────────
   ● 🔒 github-work · 已解锁保险库
     secret：sk_l••••••••••••••••••••3f2a   ← 默认掩码；[ 短暂显示 ] 5s 后自动复原

```

**设计要点：**
- 默认态**零明文、零字符**：普通引用条目连掩码都不给，只给"存在 + 存放位置 + 用途"。
- 反填**由用户主动触发**（T2 L4 约束），且视觉上明示"**由密码管理器执行，系统未接触明文**"。

- 全站账号引用相关一律 `vault/secret` 紫色 + 锁图标，形成识别心智。

## 3. 密钥相关内容的隐藏 / 脱敏呈现规则

> 目标（T2 §6.2）：知识库正文、向量索引、运行日志、导出物中**明文 secret 命中数 = 0**；secret **不进入 LLM 上下文**（或仅以占位符出现）。本节把该约束翻译成**界面呈现规则**。

### 3.1 四态呈现模型

| 呈现态 | 触发条件 | 界面上出现什么 | 是否出现明文 |
|--------|----------|----------------|--------------|
| **P0 不存在** | 该账号无账号引用 | 无任何渲染；或"密码管理器中暂无此凭据（Secret Entry）"提示 | 否 |
| **P1 存在但不可见**（默认） | 存在账号引用条目 | `🔒 账号引用 · vault:<provider>/<item>#<n>` + 存放位置 + 用途 | **否（零字符）** |
| **P2 掩码可见**（受限） | 用户显式"短暂显示" 且保险库已解锁 | `sk_l••••••••••••••••••••3f2a`（首尾各留少量字符），5s 后自动复原 | 否（仅掩码） |
| **P3 完整明文** | —— | **本系统 UI 永不呈现**。反填时由密码管理器扩展/CLI 直接写入目标字段 | 否 |

### 3.2 位置 × 呈现方式对照表

| 呈现位置 | 应出现的内容 | 禁止出现 |
|----------|--------------|----------|
| 知识库正文 / 笔记 | 引用 token：`{{secret:vault:github/pat#1}}`（等宽） | secret 明文、可推断的完整串 |
| 会话流 / AI 回答 | 引用 token 或"🔒 已引用账号（未展开）" | 明文；修改后仍带明文的旧值 |
| 召回结果卡片 | 引用 token（若命中片段含 token，则高亮为 vault 色） | 展开后的明文片段 |
| 复制/剪贴板 | 复制的是**引用**（P1）；反填是**密码管理器写入目标字段**（P3 不过 UI） | 把明文 secret 复制到剪贴板 |
| 撤销 / 审计日志 | 引用 id、使用时间、会话 id、结果（成功/失败） | secret 明文；掩码以外的字符 |
| 导出物（迁移知识库） | 引用关系 + `provider/item#n` | 任何凭据明文 |
| 向量索引 / 嵌入 | 对 token 做占位，不嵌入明文 | 明文 secret 进入 embedding |
| 截图 / 分享 | 引用态（P1）默认 | 任何明文可能入镜（编辑器中避免触发 P2/P3） |

### 3.3 呈现的硬规则（可执行）

1. **默认最严**：任何未显式请求的状态都是 **P1**，界面不含 secret 任何字符。
2. **颜色即类型**：账号引用相关内容一律 `vault/secret` 紫 + 🔒，与普通知识视觉隔离。
3. **复制即引用**：`[复制]` 按钮复制 token，不复制明文；明文只在"反填"路径由密码管理器处理。
4. **不落日志、不入上下文**：UI 层不缓存、不写日志、不把明文送进对话；P2 明文 5s 自动复原。
5. **失败也脱敏**：填充失败提示只报 `provider/item#n` 与错误码，不回显任何 secret 片段。
6. **降级不可回退到明文**：若保险库未解锁，只能引导用户去解锁密码管理器，**不得**在知识系统内以任何方式展示明文。

### 3.4 反例（明确禁止的呈现）

- ❌ 在确认卡或结果卡里展示 `password: ********` 之后附"点击显示明文"。
- ❌ 把 secret 写进会话消息 / URL 查询参数 / localStorage。
- ❌ 用"提示前 3 位"当作安全展示（可暴力拼接 → 禁止超出 P2 的首尾留位规则）。
- ❌ 在导入预览里原样回显笔记中的明文 secret（应就地替换为引用 token 并在"丢失/脱敏清单"标注）。

### 4.3 可访问性要求（WCAG 2.1 AA 为基线）

| 维度 | 要求 |
|------|------|
| **对比度** | 正文与按钮文字 ≥ 4.5:1；大字号(≥18.66px 或 14px 粗体)与 UI 图形 ≥ 3:1；状态边条对比相邻底色 ≥ 3:1 |
| **非颜色依赖** | 所有状态"颜色 + 图标 + 文字标签"三件套；色盲用户不因缺色丢信息 |
| **键盘可达** | 全部操作可键盘完成：Tab 顺序 = 视觉顺序；确认卡三按钮可 `Tab` 到达，`Esc` = 放弃，主操作可 `Enter` |
| **焦点可见** | 全站统一焦点环（`2px accent.primary`），永不移除 outline，暗/浅两主题均 ≥3:1 |
| **屏幕阅读器** | 系统卡使用语义化区域（`region` + 标题）；确认卡 `role=alertdialog`，出现即 `aria-live=assertive` 播报"待确认写入"；账号引用向 AT 声明为"账号引用（内容不可见）"，**不播报掩码字符** |
| **状态可感知** | 写入结果、导入进度、反填结果用 `aria-live=polite` 播报，不依赖纯视觉边色 |
| **动效减弱** | 尊重 `prefers-reduced-motion`：掩码复原、卡片进出改为即时切换，不播放动画 |
| **目标尺寸** | 交互目标 ≥ 44×44px；密集卡片中按钮不缩到不可点 |
| **错误预防** | 删除/撤销等破坏性操作二次确认；可撤销窗口内提供"撤销"（T2 §6.3） |
| **文本缩放** | 200% 缩放下不重叠、不截断关键信息（卡片允许纵向增长） |
| **语言/编码** | 中英混排；账号引用 token 用等宽且 `aria-label` 说明用途，避免角标符号被误读 |
